# Аэрохоккей на двоих

Веб-игра для двух человек на одном iPhone. Телефон лежит между игроками,
каждый держит свою половину поля. **Ворота верхнего игрока — это Dynamic
Island:** шайба заезжает под него и физически исчезает. Нижние ворота —
нарисованное зеркало острова, той же формы и в той же позиции.

Собрано под iPhone 15 Pro (393×852 pt, остров 125×36.67 pt с отступом 11 pt),
но геометрия читается из `env(safe-area-inset-*)` и подстраивается под
другие модели.

## Как играть

Каждый игрок водит пальцем по своей половине — бита следует за пальцем и не
может пересечь центральную линию. Два касания обрабатываются независимо:
игрок определяется по половине, в которой палец коснулся экрана первым.

По умолчанию матч до 7 голов — это стандарт настоящего аэрохоккея.
В настройках есть режим на время (2/3/5 минут); при ничьей на исходе времени
включается золотой гол. Отдельными тумблерами отключаются звук, шлейф шайбы,
вспышки от ударов и тряска при голе.

## Запуск локально

```bash
python3 -m http.server 8000
```

Открыть `http://localhost:8000`. На телефоне в той же сети — по локальному IP
компьютера. Service worker и «На экран Домой» полноценно работают только по
https, поэтому для настоящей игры нужен деплой.

## Публикация на GitHub Pages

1. Создать репозиторий на GitHub (публичный — Pages для приватных требует платного плана).
2. Из этой папки:

```bash
git init && git add -A && git commit -m "Аэрохоккей на двоих"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/hockey.git
git push -u origin main
```

3. В репозитории: **Settings → Pages → Source: Deploy from a branch → main / (root) → Save**.
4. Через минуту игра будет по адресу `https://ВАШ_ЛОГИН.github.io/hockey/`.

Все пути в проекте относительные, поэтому подпапка репозитория в URL ничего
не ломает.

## Установка на iPhone

Открыть адрес в **Safari** (не в Chrome — там нет установки на домашний экран),
затем «Поделиться» → «На экран Домой». Запускать нужно с иконки: только тогда
пропадает адресная строка, поле дотягивается до острова и работает офлайн.

## Что нужно знать

**Часы и батарея.** В веб-версии статус-бар не спрятать — часы слева и батарея
справа от острова видны всегда. Поэтому кнопка паузы одна, в мёртвой зоне
внизу слева: сверху её некуда поставить, не задев системные значки.

**Вибрация — её нет, и это не лень.** `navigator.vibrate` в Safari на iOS не
реализован ни в одной версии. Единственный рабочий обход — системный тик
переключателя `<input type="checkbox" switch>` (iOS 17.4+). Замер на
iPhone 15 Pro (`design/haptics-test.html`) показал, из каких контекстов он
срабатывает:

| контекст | отклик |
|---|---|
| `click` | есть |
| `touchend` | есть |
| `setTimeout` через 300 мс после жеста | есть |
| `requestAnimationFrame` после жеста | есть |
| `pointerdown` | нет |
| `setTimeout` через 3 с после жеста | нет |
| `pointermove` во время движения пальца | нет |

Отсюда видно правило: тик требует «права на отклик», которое выдаёт
**завершённый** жест — `touchend` или `click` — и которое живёт пару секунд.
Начало касания его не даёт. А в аэрохоккее палец прижат к экрану всю атаку,
`touchend` не происходит вовсе, значит права нет и взяться ему неоткуда.
**Вибрация на ударах и голах невозможна в вебе на iOS в принципе.**

Поэтому тумблера вибрации в настройках нет: он обещал бы то, чего система не
даст. Тик остался там, где работает честно, — на нажатиях кнопок интерфейса.
Если Apple когда-нибудь добавит `navigator.vibrate` или Web Haptics, вернуть
отклик в игру — это несколько строк в `js/game.js`.

**Свайп «домой».** Поле кончается за 60 pt до нижнего края, поэтому палец
нижнего игрока никогда не заходит в зону системного жеста и не сворачивает
игру в разгар матча.

**Обновление.** Service worker работает по схеме «сначала сеть» — новая версия
приезжает при первом запуске с интернетом. Если правите файлы, поднимите
`CACHE` в `sw.js`, чтобы старые ресурсы гарантированно вычистились.

## Тесты

```bash
node test/physics.test.mjs
```

Двадцать проверок физики: засчитывание голов, отскоки от бортов и штанг,
отсутствие туннелирования шайбы сквозь биту на скоростях до 5000 px/s,
удержание шайбы в поле при зажиме между битой и бортом, неприкосновенность
шайбы во время вбрасывания.

## Структура

```
index.html            разметка и оверлеи (стартовый экран, пауза, настройки, финал)
app.css               оформление DOM-слоя, переменные тем
js/device.js          размеры экрана, safe area, геометрия острова и ворот
js/settings.js        настройки в localStorage
js/physics.js         симуляция: подшаги, столкновения, створы
js/input.js           два независимых касания
js/themes.js          темы Void и Ink: фон стола и спрайты
js/render.js          отрисовка кадра
js/audio.js           синтез звука на WebAudio, без файлов
js/haptics.js         тактильный отклик на кнопках (и почему только на них)
js/game.js            состояния матча и игровой цикл
js/ui.js              экраны и настройки
sw.js                 офлайн-кэш
design/styles.html    четыре варианта оформления, из которых выбраны Void и Ink
design/make-icons.py  генератор иконок (чистый Python, без зависимостей)
design/haptics-test.html  щуп: из каких контекстов iOS отдаёт тактильный отклик
test/physics.test.mjs проверки физики
```

## Задел на будущее

Бонусы (вторая шайба, изменение размера биты, ускорение) в UI не вынесены, но
код к ним готов: физика оперирует одной шайбой и двумя битами через явные
объекты, события столкновений уже собираются в общий список и обрабатываются
в одном месте (`handleEvents` в `js/game.js`), а эффекты и звуки подписаны на
эти события — новый тип события добавляется без переделки цикла.
